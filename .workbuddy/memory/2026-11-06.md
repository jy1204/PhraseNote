## 修复：移动热点场景下手机发现不了电脑（mDNS 广播 IP 选错）

- **现象**：手机连电脑的 Windows 移动热点后，手机的"发送/接收"面板里"未发现设备"；但电脑端能发现手机（不对称）。
- **根因（双层，均从依赖库源码核实）**：
  1. `local-ip-address` 0.6.13 的 Windows 实现只从"持有默认路由的网卡"取 IP（`windows.rs` 先查 `GetIpForwardTable` 过滤 `dwForwardDest==0`）。电脑连着路由器又开热点时，默认路由在路由器网卡 → 取到 192.168.1.x，热点网卡 192.168.137.1 被跳过。
  2. `mdns-sd` 0.11.5 应答查询时走 `handle_query → add_answer_with_additionals → get_addrs_on_intf → valid_ip_on_intf`，只回答与"查询到达网卡"同网段的 A 记录；不符就 `return`（debug 日志 "No addrs on LAN of intf"），一条应答都不发。手机查询从热点网卡进来 → 注册 IP 192.168.1.x 网段不符 → 静默 → 手机什么都收不到。
  3. 反方向（电脑找手机）天然通：Android 的 `local_ip()` 取的是 Wi-Fi 接口 IP = 192.168.137.x，与电脑查询到达的热点网卡同网段 → 正常应答。
- **版本澄清（用户问"3e29409 为什么可以"）**：3e29409 的发现代码与当前 HEAD 功能完全一致（start_broadcast/start_scan/前端调用时机/启动装配/依赖版本 mdns-sd 0.11.5 + local-ip-address 0.6.13 + if-addrs 0.13.4 全部相同；当时代码在 lib.rs 1472 行单文件里，v0.2.1 才拆到 core/device.rs）。**版本不是变量，网络场景才是**：都连路由器 Wi-Fi 或电脑只开热点不连路由器 → 任何版本都能发现；电脑连路由器+手机连电脑热点 → 任何版本都发现不了。
- **修复**：`core/device.rs` 新增 `pick_advertise_ipv4()`——用 `list_afinet_netifas()`（公开 API，返回全部网卡，不受默认路由限制）枚举所有 IPv4，优先选 192.168.137.0/24（Windows 移动热点固定网段），没有再退回 `local_ip()`；`start_broadcast` 改调它。Android 走 linux 模块同样导出该 API，双端安全。
- **遗留待办**：① Windows 防火墙公用网络入站规则（UDP 5353 mDNS + TCP 51234 HTTP 收发）需放行，否则发现修好后传输可能被拦；② 前端提示文案"同一个 Wi-Fi 网络"建议改为"同一网络（电脑热点也可以）"；③ Android 接收组播理论上需 MulticastLock（用户机型此前正常，未处理）。

- **克隆体样式与原条目不一致**：克隆体原挂在 `document.body`，作用域样式全部命中不了（padding、`.phrase-actions` 绝对定位、按钮尺寸全丢）→ 改挂到 `el.closest('.el-card__body')` 子树内，作用域样式全部命中；并去掉克隆体额外的 box-shadow/background 覆盖，做到"样式保持不变"。原条目改为 `visibility:hidden` + `::before` 虚线框（`visibility:visible` 让虚线可见）表示落位。

- **上移/下移不滚到目标位置 + 向上插入/添加按钮后位置有偏差（根因：用了 getBoundingClientRect）**：Vue transition-group 的 FLIP 动画期间元素带 transform，rect 量到的是"动画中间态/旧位置"，且 `scrollIntoView` 会连带滚动外层容器。改用 `offsetTop/offsetHeight`（布局坐标，不受 transform 影响）自行算目标 `scrollTop`，只动 `.demo-collapse` 这一个滚动容器。另新增 `settleThenScroll()`：插入的空条目其高度会被 EP 的 `el-input autosize`（setTimeout 里改 textarea 高度）在挂载后才确定，必须逐帧等高度稳定再定位，否则按未稳定高度算出的目标必然偏。

**新增/改动的 API**（PhrasePage.js）：`scrollWrapTo/wrap` → `scrollPhraseIntoView(uid, align)` → `settleThenScroll(uid, align)`；拖拽落点判断改为 `insertIndexFor(clientY)`（返回"移除自身后"的下标，与 `moveTo(from,to)` 语义一致）。`drag` 对象新增 `pressHeader` 字段。

## 追加：自动滚动改为 rAF 帧循环（停留也持续滚）

用户要求：「只要超出 .panel>form .el-card__body 就自动滚动视口，别管停留还是移动」。

**根因**：原先自动滚动是在 `onDragMove`（pointermove 事件）里调用的 —— 事件只在指针**移动**时触发，指针停在卡片区外不动时就没有事件 → 滚动中断。

**改动**（PhrasePage.js）：
- 新增帧循环 `dragFrame()`：每帧根据 `drag.pointerY`（最近一次指针 Y）重新判定并滚动，**与指针是否移动完全无关**；停留/移动行为一致。
- `onDragMove` 精简为：① 记录 `drag.pointerY = e.clientY`；② 阈值判定（手柄 0 / 标题 6px）；③ `positionClone` 跟手。**自动滚动与落点重算全部移出事件处理**，交给帧循环。
- 帧循环内落点重算加了守卫：`if (scrolled || clientY !== drag.lastFrameY)` —— 指针没动且没滚动时跳过，避免每帧做无谓的 DOM 查询与布局读取。
- `autoScroll` / `autoScrollViewport` 改为返回布尔值（是否真的滚动了），供帧循环判断要不要重算落点。
- 生命周期：`beginDrag()` 末尾 `startDragLoop()`；`onDragEnd()` 开头 `stopDragLoop()`（cancelAnimationFrame）；`onUnmounted` 里也停一次 + 摘掉全局 pointer 监听，防止组件卸载时 rAF 泄漏。

**新增字段**：`drag.pointerY` / `drag.lastFrameY` / `drag.rafId`；**新增函数**：`dragFrame` / `startDragLoop` / `stopDragLoop`。

## 追加：修复向上自动滚动时的"晕"感（FLIP 污染 + 速度失控）

用户反馈「拖动时向上自动滚动的动画切换看起来有点晕」。定位到 **3 个叠加原因**：

### 根因 1（主因）：FLIP 动画基线被污染，动画反复重启
Vue 的 TransitionGroup 用 `getBoundingClientRect()` 测量位置，而**该测量包含元素当前未归零的 transform**。
拖拽自动滚动时每帧都在 `moveTo` 重排 → 上一帧的 0.28s FLIP 动画还没结束，下一帧就重新测量
→ 基线带着上个动画的 transform 偏移 → 动画朝错误起点滑 → 反复打断重启 = 视觉"晃"。
滚动中重排间隔（97~231ms）远小于 FLIP 时长（280ms），动画重叠 1.2~2.9 次。

**修复**：滚动期间抑制 FLIP。
- 新增 `html.pn-no-flip` class（**挂在 `<html>` 上而非列表元素** —— Vue 永远不会 patch `<html>` 的 class，不会被渲染流程覆盖）。
- CSS：`html.pn-no-flip ... .phrase-list .flip-move { transition: none; }`。
- 依据：`hasCSSTransform()` 会克隆第一个子元素 + 加 moveClass 后用 `getComputedStyle` 检测 → transition:none → `hasTransform=false` → Vue 整轮跳过 FLIP，条目直接 snap 就位。滚动本身已是连续运动，snap 反而更稳。
- `setFlipSuppressed(on)` 开关；`onDragEnd` 与 `onUnmounted` 都要复位。

### 根因 2：滚动速度与帧率绑定（高刷屏上快一倍）
旧代码用「每帧固定像素」：列表 4px/帧 → 60Hz=240px/s、120Hz=480px/s。
**修复**：改为 **px/秒**（`dt = (ts - lastTs)/1000`）。新增常量 `LIST_SCROLL_SPEED=260`、`VIEWPORT_SCROLL_MIN=140`、`VIEWPORT_SCROLL_MAX=560`。

### 根因 3：视口滚动速度随距离暴涨
旧：`delta = min(24, max(4, 超出距离/4))` px/帧 → 超出 96px 就到 **1440px/s**（飞一样快）。
**修复**：`speed = VMIN + 超出距离*6`，封顶 560px/s → 超出 96px 时只有旧值的 39%。

**新增字段**：`drag.lastTs`；**新增常量**：`LIST_SCROLL_SPEED` / `VIEWPORT_SCROLL_MIN` / `VIEWPORT_SCROLL_MAX`；**新增函数**：`setFlipSuppressed`。

**关键经验**：Vue TransitionGroup 的 FLIP 测量用 `getBoundingClientRect()`，**含当前 transform** → 快速连续重排时动画会自我污染。凡是"拖拽 + 自动滚动 + FLIP"组合，都要在滚动期间关掉 FLIP。

## 追加：落点不再被钉到"最新的位置"（夹回可见窗口）

用户反馈「到达特定位置不用强制滚动到最新的位置，自然点就好」。

**根因**：`insertIndexFor` 用指针的**内容坐标** `contentY = clientY - wrapRect.top + wrap.scrollTop`
与所有条目的中线比对。指针拖到列表外很远时，contentY 会远超所有条目中线 →
`k` 直接冲到数组末尾 → **落点被钉在列表最后一项（"最新的位置"）**。
后果：落点预览（那条淡色内容映射）被推到视口外看不见，要一路滚到底才知道会落在哪。

**修复**：新增 `clampContentY(wrap, clientY)`，把指针内容坐标**夹回列表可见范围**
（`[scrollTop, scrollTop + clientHeight]`），`insertIndexFor` 改用它。

**效果**（模拟验证，12项/视口5项、指针在列表下方400px）：
| scrollTop | 可见窗口 | 修复前落点 | 修复后落点 |
|---|---|---|---|
| 0   | 第1~5项  | 第9项 ★看不见 | 第5项 ✓ |
| 300 | 第4~8项  | 第12项 ★看不见 | 第8项 ✓ |
| 700 | 第8~12项 | 第12项 | 第12项 |

落点始终在视口内可见，随滚动**逐项自然推进**，不再强制跳到最新位置。

**新增函数**：`clampContentY`（`contentYOf` 保持原样，只作为 raw 值来源）。

| 600 | **142px** | 124px | **1.15 条** | **1.83 屏/秒** |
| 700 | 222px | 124px | 1.79 条 | 1.17 屏/秒 |
| 900 | 382px | 124px | 3.08 条 | 0.68 屏/秒 |
| 1100 | 542px | 124px | 4.37 条 | 0.48 屏/秒 |
→ 同一份代码，600px 下"屏/秒"是 1100px 的 **3.8 倍**。用户看到的"特别快"就是这个：
矮窗口里列表可视区只剩 142px（面板 `height:80dvh` + 类型/关键词行 + 按钮行把空间吃光），
一屏刚看到就翻过去了。**不是速度值变了，是"每屏被刷过几次"变了。**

**修复**：改为按"每秒滚过多少屏"定义速度，与可见列表高度成比例
（`LIST_SCROLL_SCREENS_PER_SEC=0.7`，夹在 [70,320] px/s），新增 `listScrollSpeed(wrap)`。
实测修复后：600/700/900/1100px 均为 **0.70 屏/秒**（1100 因封顶为 0.59），手感一致。

### 根因 2：矮窗口下"向下"比"向上"更快（方向不对称）
旧 `autoScrollDrag` 先判"指针超出 .el-card__body → 滚外层视口"，命中就 `return true`，
**列表那一帧就不滚了**。而面板是 `position:fixed`，外层 `.container` 是 100dvh、
实测外层可滚范围只有 16px（body margin 造成）→ 外层滚两下就到底，
于是"向下"多出一段"外层先滚、列表空转"的空档，观感上就是**向下更快、更窜**。
**修复**：改成**列表优先**——先滚列表（列表才是唯一能露出更多内容的轴），
列表滚不动（已到头/到尾）时才回退滚外层视口。

### 根因 3：CSS 滚动锚定（overflow-anchor）与手动 scrollTop 打架
浏览器"滚动锚定"在列表内容重排时会自动调整 scrollTop 以保持锚定元素位置，
与拖拽时手动写 scrollTop 互相抵消。实测矮窗口下 90 帧只走了 184px（应为 360px），
且出现 ±120px 的瞬时跳变、抖动 σ=21.5px。
**修复**：拖拽期间给 `<html>` 加 `.pn-dragging` → `overflow-anchor: none`；
新增 `setDraggingClass(on)`，在 `beginDrag()` 置位、`onDragEnd()` 与 `onUnmounted()` 复位
（挂在 `<html>` 上，Vue 不会 patch 它的 class）。

### 修复后实测对比（600px 窗口）
| 指标 | 修复前 | 修复后 |
|---|---|---|
| 滚动速度 | 260px/s = 1.83 屏/秒 | 99px/s = **0.70 屏/秒** |
| 90 帧实际滚动 | 184px（被锚定吃掉一半） | 304px（足量） |
| 帧间抖动 σ | 21.49px | 18.59px（向上 0.00px） |
| 向上方向 | 同样快且抖 | 0.85 屏/秒，σ=0 |

### 关键经验
- **"窗口高度不同 → 同一份滚动代码手感差几倍"**：凡是把滚动速度写成固定 px/s，
  都要检查"可视区高度"这个变量 —— 屏/秒才是用户感知的量，不是 px/s。
- **position:fixed 的浮层里，"滚外层"通常没用**（外层可滚范围可能只有十几 px），
  应优先滚内容自身。
- **CSS overflow-anchor 会和手动 scrollTop 打架**，需要精确控制滚动时必须关掉。

**改动文件**：`src/assets/js/PhrasePage.js`（常量 + `listScrollSpeed()` +
`autoScroll()` + `autoScrollDrag()` + `setDraggingClass()` + beginDrag/onDragEnd/onUnmounted 挂钩）、
`src/assets/css/public/PhrasePage.css`（`html.pn-dragging ... .demo-collapse { overflow-anchor: none; }`）。
`npx vite build` 通过。

## 追加：修复"600px 窗口自动滚动特别慢"（上一条修复的副作用，双根因）

用户反馈修复后又变慢。定位到 **2 个叠加原因**，都是上一条修复引入的：

### 根因 1：把速度统一成"屏/秒"，但内容单位是固定 px 高的卡片
上一条把 260px/s 改成 0.7 屏/s（`vh * 0.7`）。600px 窗口 `.demo-collapse` 只有 142px
→ 99px/s（原值的 38%）。而每条短语卡片固定 ~124px、**不随窗口缩放**：
0.7 屏/s 在 600px 只有 **0.8 条/秒**（推进一条要 1.25s），900px 却有 2.2 条/秒。
用户感知的是"每秒划过几条 / 等多久看到下一条"，不是"每秒划过几屏"，于是显得特别慢。
`LIST_SCROLL_MIN=70` 也没兜住（99 > 70）。

**修复**：速度改为 `max(屏速, 条速)` 再夹 [70,320]。
新增 `LIST_SCROLL_ITEMS_PER_SEC=1.2`、`listScrollSpeed(wrap, itemHeight)` 加第二参数；
`beginDrag()` 里用 `offsetHeight` 平均值量一次典型条目高度存 `drag.itemHeight`（布局坐标，
不受 FLIP transform 影响；只量一次避免每帧读布局），`onDragEnd` 复位。
数值：600px 99→**149px/s（1.05 屏/s、1.2 条/s）**；700/900/1100 完全不变（155/267/320）。
仍远低于原来 1.83 屏/s 的"飞"，不会把上一条问题带回来。

### 根因 2：「列表永远优先」把外层视口滚动饿死了
上一条为解决"向下更窜"把 `autoScrollDrag` 改成列表优先、命中就 return。
但 `.demo-collapse` 是 `height:100%` 填满 `.el-card__body` 的，两者上下边界几乎重合 ——
指针**一超出卡片区，同时也落在列表边缘 24px 阈值内** → `autoScroll()` 每帧都命中并
`return true` → `autoScrollViewport()` 永远轮不到执行。
而外层在 600px 下可滚范围只有十几 px（body margin），即便跑到也两下到底 →
拖出卡片区后"自动滚动视口"几乎不动，叠加根因 1 的 99px/s，整体就是"特别慢"。

**修复**：`autoScrollDrag` 改为「出界时视口优先，视口这一帧没滚成（已到边界）立即回退列表」：
```js
if (outside && autoScrollViewport(clientY, dt)) return true
return autoScroll(clientY, dt)
```
两个轴都能持续推进，不出现空档。因为速度已按屏比例、锚定已关、FLIP 滚动期已抑制，
恢复视口优先不会重现上一条"向下窜"的问题。

**关键经验**：
- 列表是**固定 px 高的卡片**时，"屏/秒恒定" ≠ "手感恒定"，要同时约束**条/秒**；
  纯文本流才适合单用屏/秒。
- 两个滚动容器边界几乎重合时，"A 优先且命中即 return"会让 B 彻底饿死；
  应改为「A 优先，A 滚不动立刻回退 B」，而不是「A 优先，命中就结束」。

`npx vite build` 通过（未真机手感确认，参数 0.7 / 1.2 可按手感微调）。

## 定稿：拖拽自动滚动改回「固定速度」，放弃一切速度算法

用户拍板「改成固定速度，不依靠算法」。上一条的屏速/条速混合模型**全部撤销**：

- 删除 `LIST_SCROLL_SCREENS_PER_SEC` / `LIST_SCROLL_ITEMS_PER_SEC` / `LIST_SCROLL_MIN` /
  `LIST_SCROLL_MAX` / `VIEWPORT_SCROLL_MIN` / `VIEWPORT_SCROLL_MAX` 六个常量与
  `listScrollSpeed()`；删除 `drag.itemHeight` 字段、beginDrag 里的条目高度测量、onDragEnd 复位。
- 新增**唯一常量** `AUTO_SCROLL_SPEED = 200`（px/秒），列表贴边滚动与外层视口滚动共用；
  视口不再按"超出距离 × 6"加速、不再封顶 560。调快慢只改这一行。
- 选 200 的依据：历史 260px/s 在 600px 窗口被用户判为"特别快"（1.83 屏/s），
  99px/s 被判为"特别慢"；200 居中（600px = 1.41 屏/s、900px = 0.52 屏/s）。
- **保留**（非速度算法，删了会出 bug）：① `dt` 时间步长，仅把 px/秒换算成每帧距离，
  保证 60Hz/120Hz 一致；② `autoScrollDrag` 的「出界视口优先、视口到底回退列表」调度，
  以及 `pn-dragging`（关 overflow-anchor）/ `pn-no-flip`（滚动期抑制 FLIP），
  这几项是前几轮修"晕/跳/不动"的成果，与速度算法无关。

`npx vite build` 通过；Grep 确认无算法常量/函数残留。未真机手感确认。

## 追加：手机端触摸拖拽修复（标题拖不动 / 克隆体残留）

用户报 3 个现象：① 手机上按标题拖动没反应、只有按手柄能拖；② 疑似只有第一条能按标题拖；
③ 拖一条时再拖另一条，上一条的克隆体停在那里不消失。同时确认要加「按下时长检测」。

### 根因
1. **标题拖不动**：`.phrase-content-box { touch-action: manipulation }`（CSS:513）允许浏览器原生
   竖向滚动；手指一滑，浏览器发 `pointercancel` → `onDragEnd` 立即清理，克隆体还没跟上就被取消。
   手柄有 `touch-action:none`（CSS:541）所以唯一能拖。
   ⚠ 关键约束：**touch-action 在 pointerdown 时就被浏览器锁定，手势开始后动态改无效**，
   所以不能"先允许滚动、判定为拖拽再改 none"。
2. **克隆体残留**：`onDragStart` 每次 pointerdown 都直接 `drag.clone = null` 覆盖旧引用，
   **没有把旧克隆体从 DOM 移除**。手机多指 / 快速连拖时上一轮还没 pointerup 就又按下
   → 旧节点永久留在 `.el-card__body` 里（`.dragging-clone` 已有 `pointer-events:none`，
   所以只是视觉残留，不拦事件，但看起来就是"停在那里不消失"）。

### 修复（PhrasePage.js + PhrasePage.css）
- CSS：`.panel>form .el-card__body .el-collapse-item__header` 加 `touch-action: none`，
  标题区手势完全交给 JS；内容区仍 manipulation 可原生滚动。
- 新增常量 `DRAG_INTENT_MS=150`、`SCROLL_INTENT_PX=8`（PhrasePage.js:612-613）。
- 新增 `resetDrag()`（:645）：移除旧克隆体、停帧循环、复位 FLIP/锚定 class、摘监听；
  `onDragStart` 开头统一调用 → 重入不再泄漏克隆体。
- 触摸手势分流（`onDragStart` + `onDragMove`）：
  · 桌面 mouse + 拖拽手柄：完全不变（6px / 0px 即拖）。
  · 触摸按在**非标题、非手柄**区域：直接 return，留给浏览器原生滚动查看。
  · 触摸按在**标题**：`intent='pending'` 意图窗口 —— 150ms 内竖向位移 >8px 且竖向为主
    → `intent='scroll'`，由 JS `wrap.scrollTop = startScroll - dy` 1:1 跟手代滚，不生成克隆体、
    不重排；按住 ≥150ms 再移动 / 水平为主 → `intent='drag'`，走原拖拽链路。
  · scroll 分支置 `drag.moved=true`，复用 onDragEnd 的 click 抑制器挡住滑动后误展开。
- `drag` 新增 `startTime`（performance.now，不依赖 event.timeStamp）/ `intent` 字段，onDragEnd 复位。

### 交互约定与已知限制
- 手机上：**按住标题约 150ms 再移动 = 拖动排序；按下直接滑 = 滚动查看；手柄仍是按下即拖**。
- 标题区因 touch-action:none，滚动由 JS 代滚 → **没有惯性和回弹**（原生滚动只在内容区可用）。
- 用户那句"只有第一个在拖动状态下才能根据 head 直接拖"未能完全对上具体现象，
  推测是残留克隆体造成的视觉混淆；已请其真机复测确认。

`npx vite build` 通过；未真机验证。

## 安卓 logcat `E GPUAUX: [AUX]GuiExtAuxCheckAuxPath:667: Null anb` 定性（17:05 用户实测日志）

**结论：厂商图形栈的无害噪声，不是 app 报错，应用侧无法根除。** 结论基于多源交叉核对
（SO 73148381 / 76697131、Home Assistant Companion 社区帖、flutter_inappwebview#2124、
MAUI/Blazor WebView issue、Dioxus#1762、Tauri Android dev 社区帖），这些案例全都是
**WebView 类应用 + 应用功能正常**。

- `anb` = `ANativeWindowBuffer`；`GuiExt`/`GPUAUX` 是 MTK（联发科）系 ROM（OPPO/一加/realme
  等 ColorOS 也带）的图像增强/辅助显示扩展。它每帧检查 aux path 想取 native buffer，
  WebView 的 GPU 合成层给不出可识别的 anb → 打 E 级日志后直接返回，**非崩溃、非空指针崩溃**。
  数字 663/667/670/674 只是 ROM 版本里源码行号不同。
- 触发条件：**页面连续重绘**（rAF 循环 / CSS transform / FLIP / 滚动）。SO 76697131 明确记录
  Cordova + canvas rAF 场景「60 次/秒」刷屏；Home Assistant 是 5~15 次/秒。
  本项目 `PhrasePage.js` 的 `dragFrame()` rAF 帧循环 + `positionClone()` 每帧写 transform
  正好是同构触发模式 → 拖拽时日志变密属预期，不代表拖拽有 bug。
- **不要为它改代码**：manifest 加 `android:hardwareAccelerated="false"` 或给 WebView
  `setLayerType(LAYER_TYPE_SOFTWARE)` 虽可能减少日志，但会让刚做好的 FLIP/克隆体动画
  掉帧，性价比极低。网上「把 http 改 https / 换 AdvancedWebView」的说法针对的是别的问题——
  `GuiExtAuxCheckAuxPath` 属图形栈，与明文流量无关；改协议只会让 dev 前端（局域网 http）
  或 `tauri://localhost` 加载失败。SO 上那个 Tauri 帖子标 solved 解决的是「dev 时
  devUrl 要填 PC 局域网 IP 否则白屏」，与 Null anb 无关。
- **唯一干净办法是过滤日志**：`adb logcat GPUAUX:S *:V`；PowerShell
  `adb logcat | Select-String -NotMatch 'GPUAUX'`；Android Studio 新版 Logcat `-tag:GPUAUX`。
  只静默该 tag，别用 `*:S`（会把自己 app 日志一起屏蔽）。
- 判断是否真有害：看有无 `FATAL EXCEPTION` / tombstone / `SIGSEGV` / 黑屏花屏，
  或 `adb logcat -b crash`；没有就纯噪声。系统侧只能靠厂商 OTA / 更新 Android System WebView。

项目现状核查：`gen/android/app/src/main/AndroidManifest.xml` 无 `hardwareAccelerated`（默认 true），
`MainActivity.kt` 仅加 MulticastLock，无自定义 WebView / setLayerType / SurfaceView，
故与业务代码、Rust 后端、mDNS、短语库均无关。**本次纯答疑，未改任何代码。**
